## 2. Decisions (record in round 8, before any adapter code)

**D-011 The agent may read public metadata.** The agent may run read-only queries against the `INFORMATION_SCHEMA` views of the public dataset `bigquery-public-data.thelook_ecommerce`, with credentials the owner provides in the environment. Limits:

- Metadata views only (`TABLES`, `COLUMNS`, `COLUMN_FIELD_PATHS`, `TABLE_CONSTRAINTS`, `KEY_COLUMN_USAGE`, `TABLE_OPTIONS`). No query reads a table's rows.
- That dataset only. Any other project or dataset, and any non-public data, stays owner-run.
- Credentials come only from the environment (Application Default Credentials or `GOOGLE_APPLICATION_CREDENTIALS`) and the billing project from `FACT_BQ_PROJECT`. They are never written to the repository, a report or a log.
- Live code runs only behind `FACT_LIVE_BQ=1`. Tests and CI never need credentials; they read the committed snapshot.

Reason: a metadata snapshot of a public dataset holds no data and no secrets, and the agent can produce and refresh it faster than the owner. Plan ground rule 7 and the spec's "Agents read, people run" stay in force for everything else; record the exception in both with a link to D-011.

## 3. Round 8 - WP1.5 BigQuery adapter

Plan reference: WP1.5.

Deliverables:

- `src/factmodel/adapters/__init__.py`, `adapters/base.py` (protocol from the plan; `MetadataSnapshot` is `factmodel.model.types.Snapshot`; `FactDraft` is an entity document with `status: draft` and evidence records pinned to the snapshot).
- `src/factmodel/adapters/bigquery/` with live mode (the six views above) and offline mode (`load_snapshot`).
- `fact snapshot --source <id>`: writes `sources/snapshots/<source-id>@<YYYY-MM-DD>.yaml`, valid against `schemas/snapshot.schema.json`, and sets the source's `current_pin`.
- `fact sync --source <id> --offline` is out of scope (WP1.6); `to_facts` writes drafts through a small `fact draft --source <id>` command into `drafts/`, never into `physical/`.
- `tests/fixtures/snapshots/thelook_ecommerce@<date>.yaml`: the committed snapshot, taken live under D-011. Metadata only.
- `tests/adapters/bigquery/`: offline tests on the committed snapshot; one live test behind `FACT_LIVE_BQ=1` that takes a fresh snapshot and compares its object and field list with the committed one.
- Docs note (adapter module docstring and `spec/VOCABULARY.md` section 12): BigQuery constraints are `NOT ENFORCED`, so a declared key is `inferred` until a probe confirms it.

Rules:

- Declared foreign keys become relationships with `mechanism: declared_fk`, evidence `inferred`, `enforced: false` in the snapshot. Nothing else is guessed: no inferred joins, no classes beyond `data` as a placeholder marked in the draft, no anchor references.
- Nested fields (`COLUMN_FIELD_PATHS`) become fields with `name` and `path`; `REPEATED` mode becomes `repeated: true`.
- Pins: `bigquery:bigquery-public-data.thelook_ecommerce@<YYYY-MM-DD>`.
- Run the live snapshot once, early in the round. Report the bytes billed per query from the job statistics.

Acceptance: offline tests pass without credentials; the committed snapshot validates against its schema; drafts for every thelook table load with `fact check` when copied into a model with `users` as anchor (residue and scope stages may fail on drafts; schema, references and evidence must pass); the live test passes once with `FACT_LIVE_BQ=1` and is skipped otherwise.

## 4. Round 9 - WP1.5b git adapter

Plan reference: WP1.5b. No owner input needed.

Deliverables: `src/factmodel/adapters/git/`; DDL parsed with sqlglot into the snapshot format; any text file quotable as evidence with a `<repo>@<sha>:<path>[:<line>]` pin; `fact snapshot` for a git source stores parsed DDL plus a file list with hashes, never the repository.

Acceptance: tests build a small repository in a temporary folder with DDL in two dialects (BigQuery and PostgreSQL); a DDL snapshot and a catalog snapshot of the same table produce matching entity drafts.
