## 7. Divergences

From the brief:

- **Environment.** The shell sets `UV_PROJECT_ENVIRONMENT=/Users/Oleksandr_Sluchyk/.venvs/adp-semantic-model`. Until mid-round 6 (and in rounds 1 and 2a), every `uv sync` / `uv run` here used that venv, which belongs to another project, and synced it to this lockfile. That may have removed packages that project needs; run `uv sync` in that project to restore it. From mid-round 6 the run used `UV_PROJECT_ENVIRONMENT=.venv` (local, ignored by git). Consider unsetting the variable globally or setting it per project.
- `yaml_strict.py` (a WP1.1 deliverable) was written in round 2, because schema fixtures needed it.
- The release partition was implemented in round 5 as a pure function, so its vectors run; `fact release` stays in WP3.4.
- Round 7 has 19 cases (9 plan cases plus 10 variants) and two small core additions.
- Fixtures, vectors, gate fixtures and hard cases were generated by scratch scripts from hand-written expectations; the scripts are not committed, their outputs are.
- This final report is a separate commit after round 7.

From the plan:

- The plan's "missing basis rejected" scope vector became `missing-admission` (under D-007 a missing admission means no propagation, not a rejection).
- Extra generated file `generated/scope-rejections.tsv` and a `reachable` column in `generated/scope.tsv`.
- Release key lists are `keep` and `drop` per kind (fail-closed needs a way to drop a key on purpose).
- Duplicate register IDs are reported by the `registers` stage, not `references`.
- `gate.yaml` ships with the framework; models cannot override it yet.
