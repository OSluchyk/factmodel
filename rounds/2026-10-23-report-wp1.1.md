## 5. Confirmed / inferred / unknown

**Confirmed**

- Typed models and schemas agree on all 112 fixtures; all 18 model vectors load without issues.

**Inferred** (loader behaviour the plan did not fix)

- Skipped folders: hidden folders, `drafts/`, `generated/`, `snapshots/`, `corpus/`. Every other YAML file must have a known `kind`.
- The profile named in `factmodel.yaml` is taken from a local `kind: profile` file with that ID, else from the framework's `profiles/<id>/profile.yaml` (shipped in round 6).
- The anchor entity must exist only when the model has at least one entity, so an empty model (round 6, `fact init`) loads cleanly.
- Joins are checked: each side names the source or the target entity and an existing field (name, or path when nested).
- Each issue names its gate stage (`yaml`, `schema`, `derived-not-authored`, `references`), so the gate (round 6) runs the loader once. A derived key is reported under `derived-not-authored`, not `schema`.
- Reference checks run on the raw data of every file with a known kind, even one that failed its schema, so one schema error does not cause a cascade of reference errors.

**Unknown**

- Whether a model should be able to override a framework profile with a local file of the same ID (it can today).
