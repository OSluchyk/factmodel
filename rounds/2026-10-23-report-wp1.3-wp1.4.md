## 5. Confirmed / inferred / unknown

**Confirmed**

- Every stage has a fixture that fails it alone; the end-to-end CLI path passes; the wheel ships profiles, agent templates and the stage list.

**Inferred** (choices the plan left open)

- What each stage checks beyond the plan's one line:
  - `evidence`: a fact whose cited evidence is all retracted (the schema already requires evidence IDs).
  - `derived-not-authored`: derived keys the schema rejects plus derived keys anywhere under `extensions`.
  - `scope`: any admission rejection, and any entity a layer uses (joins, filters, concepts, measures) that is unreachable, unless an accepted decision's `about` names it.
  - `registers`: reused register IDs, gaps in numbering (an ID was deleted), an answered escalation or resolved finding whose evidence is not usable.
  - `privacy`: emails, digit runs of 9 or more, and tab- or pipe-separated row-like text in evidence quotes, notes, named errors and probe-result errors.
  - `generated-fresh`: missing, different or extra `.tsv` files in `generated/`.
- Stages `projection`, `scope` and `generated-fresh` are SKIP when a yaml, schema, derived-key or reference issue blocks computing derived values; SKIP never happens without another stage failing.
- `gate.yaml` ships with the framework; a model cannot override it yet.
- `fact init` adds `.gitkeep` to empty layout folders so git keeps them, and runs `fact project` so the new model passes `generated-fresh`.
- The model-repository `AGENTS.md` keeps "never commit": D-008 is for this framework repository only.
- The `fact-check.yml` template installs `factmodel=={version}` with `uvx`; it works only once the package is published (WP4.1).

**Unknown**

- How noisy the `privacy` patterns are on real evidence; tuned only on fixtures.

## 6. Divergences

- **Environment side effect.** The shell sets `UV_PROJECT_ENVIRONMENT=/Users/Oleksandr_Sluchyk/.venvs/adp-semantic-model`. Every `uv sync` / `uv run` in rounds 1 to 5 (and early round 6) used that venv, which belongs to another project, and synced it to this lockfile. That may have removed packages that project needs; running `uv sync` in that project should restore them. From this point the run uses `UV_PROJECT_ENVIRONMENT=.venv` (local, ignored by git).
- Duplicate register IDs moved from the loader's `references` stage to `registers`, so each fixture fails one stage only.
- `current_pin` added to the source schema; it was needed for "evidence older than its source pin" in `fact status`.
- Gate fixtures were generated by a scratch script (base model plus one change each, then `fact project`); the script is not committed, the fixtures are.
