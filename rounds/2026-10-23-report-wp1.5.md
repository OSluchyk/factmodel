## 5. Confirmed / inferred / unknown

**Confirmed**

- All checks green; the PostgreSQL path verified locally against Docker PostgreSQL 16, not only in CI.
- SQLite and PostgreSQL agree on every neutral part of the test schema except view column types (below).

**Inferred**

- Relationship keys in drafts are `to-<target>` (with the columns when one target appears twice), not the constraint name: constraint names differ by engine (SQLite often has none), so names would break cross-engine agreement.
- Entity IDs split camel case (`InvoiceLine` → `invoice_line`); `physical_name` keeps the engine's spelling.
- `enforced` applies to every constraint of an engine in `engine_enforces_foreign_keys`, not only foreign keys.
- Arrays are recorded as the element type with `repeated: true` (BigQuery `ARRAY<STRING>` and PostgreSQL `_text` alike); `type_class: array` is left for arrays whose element is unknown.
- `fact init` defaults `anchor_entity` to the slug of the profile's subject (`customer`); the `references` check of the anchor waits until the model has entities.
- Mapping blocks use a new fence, `yaml vocabulary-map:<name>`, so list blocks and their tests stay unchanged.

**Unknown**

- How the `sql` adapter reflects engines other than SQLite and PostgreSQL (no other driver installed).

## 6. Divergences

- SQLite gives a computed view column no type, so its `type_class` is `other` where PostgreSQL infers one; the neutral comparison compares view columns without type class. Recorded in the test helper.
- Two source fields beyond the brief, `revision` and `include`, were added to the source schema now for the git adapter (round 9).
- Snapshots gained optional `pin` (snapshot and object level) so `to_facts` can cite per-object pins from DDL files.
- The CI PostgreSQL service was added in this round (the brief places it in round 12), because this round's PostgreSQL test needs it.
- `compose.yaml` sits at the repository root, shared by the tests and, later, the Chinook example.
- Docker was available, so the PostgreSQL path is verified locally; pulling the `postgres:16` image was the only network use besides package installs.
