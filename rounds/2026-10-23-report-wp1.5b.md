## 5. Confirmed / inferred / unknown

**Confirmed**

- Two dialects of the same DDL, and DDL against a SQLite catalog, agree as described; composite keys, table-level unique constraints, column-level references and PostgreSQL arrays parse correctly.

**Inferred**

- Column types are written in sqlglot's neutral spelling (`DECIMAL(10, 2)`, `VARCHAR(64)`), not the dialect writer's: SQLite's writer would turn `NUMERIC` into `REAL` and change the type class.
- A working-tree read pins each file by its blob hash, so the same pin names the same content in any later commit; such snapshots have no top-level pin.
- View columns from DDL have type `UNKNOWN` (class `other`), as SQLite's catalog has.
- Each object's pin carries the line of its `CREATE` statement.
- `enforced` follows the source's `engine` (DDL only declares; the engine decides).

**Unknown**

- Parsing of dialect-specific DDL beyond SQLite and PostgreSQL (partitioning clauses, BigQuery `OPTIONS`) is untested.

## 6. Divergences

- `fact quote` is an extra command; the brief asks only that text be quotable.
- `revision: worktree` is an extra mode; it lets a model cite DDL committed in the same change (needed by the Chinook example, round 12).
