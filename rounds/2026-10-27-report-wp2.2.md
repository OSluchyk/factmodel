## 5. Confirmed / inferred / unknown

**Confirmed**

- On the same rows, SQLite, PostgreSQL and DuckDB agree on every neutral snapshot part and on all 46 probe counts.
- The committed BLS area list has 4,649 duplicated codes (measured), as `profile.md` R1 says.
- 53 industry codes have no parent one character shorter: the ranges 31-33, 44-45 and 48-49 and the 50 three-digit codes under them (measured, F-0008).
- Collation matters for join expressions. The first county filter, `substr(area_fips, 1, 1) < 'A'`, let one more row through on PostgreSQL, whose linguistic collation sorts `a` before `A`. It now reads `<= '9'`, which holds under both collations, and the relationship's meaning says why.
- **Defect in `fact probe intake` (not fixed).** For an out-of-range probe on a field (`value_set`, `null_rate`), intake writes the field reference (`qtrly.disclosure_code`) into the finding's `about`. The schema allows only an entity or a relationship there, so the gate then fails `references`. Fixing intake is a core change that D-015 to D-017 do not cover, which the brief makes a stop condition, so it is left for the owner (question 1). The example's finding F-0002 cites the entity in `about` and keeps the field in `extensions.fact`.

**Inferred**

- The area title file is two lists one after the other, the second starting with its own header line. Read from the committed file, not measured by a probe. Loaded unchanged, that line becomes a row whose code is `area_fips`, so the 4,809 "distinct codes" of `profile.md` include it.
- Relationships to `area_titles` (and `in-state`) are `many_to_many` as published, because each code meets two identical rows (F-0001). This avoids a second finding for the same cause through `fan_out`.
- The `agglvl_code` discriminator cannot be set on a single-target relationship (schema). It is in the meaning of `annual.to-industry` and `qtrly.to-industry`, and in F-0008 (`extensions.discriminator`).
- `unresolved` relationships (`in-msa`, `in-csa`, `in-nation`, `to-supersector`) carry a placeholder self-join, because the schema requires `join`. Their `missing` text says so.
- The over-the-year relationships are expression self-joins on the key with `year - 1`. Rows without an over-the-year value (all of 2024, whose prior year is not in the example) are filtered out.
- `owner-profile` has `rank: 20`: it reports the files themselves, so it outranks the layout pages (40) in F-0004.
- Document quotes are `profile.md` text, attributed to the BLS source it transcribes, or to `owner-profile` when they report a query. Every quote was checked to occur verbatim in `profile.md`.

**Unknown**

- How the real `-` rows and suppressed cells interact with over-the-year fields; the seed sets them to zero with `oty_disclosure_code` N or NULL.
- Whether the DDL types match BLS maximum lengths; the DDL follows the owner's loaded types (VARCHAR without length).

## 6. Divergences

- A fourth document source, `owner-profile`, was added: findings cite `profile.md` with query ids, as the brief asks, and the BLS documents cannot carry query results.
- Two `null_rate` probes were written by hand (the generator writes `null_rate` only for anchor fields, and QCEW has none).
- Finding ids were renumbered after intake so they follow the brief's order (intake opened them in probe-id order). Their `extensions.probe` keeps intake idempotent; a second intake writes nothing.
- The seed has 282 `annual` and 1,136 `qtrly` rows ("a few hundred" each was the brief's size).
- The DDL declares no keys, like the BLS files, so every relationship is `inferred_join` confirmed by probes, and keys come from documents and `key_duplicates`.
- `bls-titles` quotes also come from `profile.md` A4 and A7, not only A2 and A3.
