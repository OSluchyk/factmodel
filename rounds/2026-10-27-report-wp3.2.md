## 1. Outcome

`fact equivalence run` compiles every corpus request with the layer's consumer, runs both sides offline on SQLite or DuckDB, and compares them in `same_rows`, `same_count` or `same_predicate`. ## 5. Confirmed / inferred / unknown

**Confirmed**

- The same toy corpus gives the same outcomes on SQLite and DuckDB, and through the owner-run script (sqlite3 CLI) and `--results`.
- The report and `last-run.json` hold outcomes, modes and row counts, never values (tested).

**Inferred**

- Consumer and reference SQL name tables by entity id; the harness binds them to physical names and keeps the entity id as the table alias. Otherwise a consumer would need the physical layer, while `compile` receives only the layer.
- Results are compared as multisets, with numbers rounded to 6 decimal places, so integer and float renderings of the same value agree across engines.
- A consumer that raises, or returns no SQL, gives the item outcome `error`, never a failed run.
- The live script's set difference uses `EXCEPT`, which collapses duplicates, so `same_rows` there is the row counts plus both set differences. Exact multiset equality is offline only.

**Unknown**

- How the live script behaves on engines without `EXCEPT` in subqueries; not tested beyond SQLite.
