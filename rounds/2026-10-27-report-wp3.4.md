## 5. Confirmed / inferred / unknown

**Confirmed**

- Both examples release cleanly: no seeds, drafts, DDL, snapshots or agent files; entities without `extensions`; sources without `access` or `dsn_env`.
- Every refusal path is tested: unmatched file, undeclared key, failing gate, equivalence drop, unclosed marker, and a non-release output folder (never wiped).
- **Defect found and fixed.** Before this round, the model loader would have read a built release under `release/out/` as model files. The model gate then failed with 128 duplicate evidence IDs.

**Inferred**

- Internal-note markers are line markers (`internal:begin`, `internal:end`) in exported text files. Projected YAML files are re-written from their kept keys, so YAML comments do not survive projection.
- Release notes live in the release folder and carry forward from the previous release written there. `--previous` names the release to compare with.
- `fact release` writes outside the model only. It reads the source commit with `git rev-parse HEAD`, or writes `unknown`.
- The `release` stage also runs the derived-key check, so "derived keys never leak" is checked on the release itself.

**Unknown**

- How the notes should carry forward when a release is built in a fresh folder, for example in CI; today `--previous` must point at the earlier release.

## 6. Divergences
