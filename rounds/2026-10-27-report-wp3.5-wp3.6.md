## 5. Confirmed / inferred / unknown

**Confirmed**

- **Ossie page.** https://ossie.apache.org/ was read once on 2026-10-27. It names the project "Apache Ossie (incubating)" and links the core specification at https://github.com/apache/ossie/blob/main/core-spec/spec.md. It states no version and names no JSON Schema.
- **dbt install.** `dbt-core` 1.12.6 and `dbt-duckdb` 1.11.1 installed cleanly; no other dependency moved (duckdb 2.0.0, SQLAlchemy 2.1.6, sqlglot 30.24.0, pydantic 2.14.1).
- **dbt parse.** It accepts both exports once the project holds a MetricFlow time spine. The QCEW metrics carry the disclosure filter as a MetricFlow `where` filter.

**Inferred**

- **Ossie version pin.** Pinned as "not stated (main, as shown on ossie.apache.org on 2026-10-27)". The exporter writes only the keys the page's example shows. Joins, required concepts, hazards and evidence status go into `ai_context.instructions`, the one free-text place that page shows. The brief's fallback ("pin the last version named in `spec/SPEC.md`") gave nothing either, since SPEC names no version.
- **What dbt cannot hold.** Measures with aggregation `none` (`avg_weekly_wage`, `annual_employment`) are not exported to dbt. MetricFlow needs a hand-written derived metric for a formula over aggregates; this is listed in `EXPORT_NOTES.md`.
- **Time spine.** It is dbt project infrastructure, so the export does not write one; the round-trip notes say so.

**Unknown**

- **Ossie fidelity.** How faithful the Ossie export is to the full specification: the document was not read.
- **The CI run.** Whether `dbt parse` behaves the same in CI; it has not run there (nothing pushed).

## 6. Divergences

- **One small extra network request.** Running `dbt --version` once to confirm the install made dbt check PyPI for its latest version; this went beyond the package install. Since then, every dbt call runs with `--no-version-check` and tracking off (`DBT_SEND_ANONYMOUS_USAGE_STATS=false`, `DO_NOT_TRACK=1`).
- `ossie` was added to `export_target` rather than renaming `osi`. A rename would be a decision under D-018.
